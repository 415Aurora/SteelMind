# 办公楼完整荷载课程案例

本模块提供参考平面基础上的四层办公楼上部钢框架课程设计，包括G、办公/楼梯/屋面Q、四向风及水平地震、152个活载分区、偶然偏心、CQC、双向效应、318个组合、柱弦P-Δ、构件验算和同源成果。它是已采用设计边界下的数值设计，不代表连接、楼板、柱脚、基础和实际工程全部完成。

## 网页操作

1. 启动项目现有前后端；已有隔离环境继续使用，勿向Conda/base安装依赖。
2. Safari打开本地网页，更新后按Option+Command+R重新载入。
3. “连接与知识库”点击“载入办公楼完整荷载课程案例”。该操作明确切换至参考图重建的新布置，不把任意Excel自动转换成办公楼方案。
4. 在“工程流程 → 截面迭代与优化”检查楼面/屋面恒活载、基本风压和采用特征周期。修改后点击“应用案例参数”。
5. 点击“运行工作流2”，或在已配置支持工具调用的模型后，在对话中说“请分析已载入的办公楼完整荷载课程案例，并说明上部框架验算与建筑交接状态”。参考截面先算，随后按候选4进行保守改型；不是经济最优搜索。长任务持续显示阶段和进度，可停止。
6. 在“模型与成果 → 三维模型展示”点击“生成/更新三维模型”。分析后可选择G、三类Q、四向W实际静力工况；内力图为该实际工况有符号结果，验算颜色来自完整组合保守包络。谱/组合包络不会伪装成一组同时内力。
7. 点击对话旁“生成计算书/图纸”或工作流3按钮，下载DOCX、同源PDF、XLSX、二维切片DXF/PDF、原始XYZ三维DXF及ZIP。原始XYZ图仅下载用CAD打开，不压扁到二维预览。
8. 需要回到旧Excel自重案例时，重新上传该Excel。上传或切换会话后，办公楼状态清除，不复用旧结果。

没有模型API Key也可使用工作流按钮或命令行。真实服务商自然语言选工具行为由所配置模型决定；工程计算不依赖大模型编造过程。

## 命令行

已按项目README安装独立虚拟环境后，在项目根目录执行：

```bash
bash scripts/run_office_case.sh --validate-only
bash scripts/run_office_case.sh --output artifacts/office-demo
```

Mac也可双击`run_office_case.command`。默认候选为0和4；希望逐个验证中间方案可用`--schemes 0,1,2,3,4`。只验证最终候选可用`--schemes 4`，该结果的迭代列表不包含本次未重算的参考方案。`--input examples/office-reference/bundle.json`显式指定输入，输出目录必须为空以避免混入旧成果。

启动脚本仅选用项目虚拟环境或明确配置的`STEELMIND_CASE_PYTHON`，不安装包、不启动网页、不修改全局环境。LibreOffice为DOCX→PDF的可选系统工具；缺失时保留DOCX并将文件生成状态标为partial。DWG转换器未配置，保留DXF/PDF并明确记录未生成DWG。

## 设计条件及适用范围

- 四层4m，平面38m×16.5m，每层28柱，308节点、540计算段、372物理构件；112柱、176主梁、84次梁。来自明确二层图及已采用标准层、楼梯洞口、屋面补梁假定，不凑参考历史552杆件。
- 初始主梁HN600×200×11×17、次梁H550×200×6×10、箱柱400×400×10×10；Q355B。最终保守候选主梁H750×400×22×30、次梁H650×350×18×25、焊接箱柱550×550×20×20，加劲肋列出尺寸、节点、承压与稳定结果，自重计入。
- 6度/0.05g/第二组/IV类/C类地面，已采用面内刚性楼板，但不作为梁受压翼缘侧向约束。Tg=0.90s为采用的平台延长值，规范表值0.75s另存。当前实现限定这套参考几何和设防条件；不支持的几何、释放、楼板布置或设防变化返回明确错误，不能修改一个字段就声称完成其他地区设计。
- G包括钢材、加劲肋、楼板/屋面、墙及楼梯承托。三层办公楼面各515m²、屋面627m²，楼梯洞口不重复加载。质量源G+0.5Q办公+0.5Q楼梯，屋面Q不计入。
- 材料设计强度与fy按板厚区分；原权威截面属性不覆盖，新焊接截面明确为理想几何。Q355勘误值已与公开转载原始表图核对，保留非出版社原发认证说明。
- 数值方法：仅柱弦全局P-Δ，梁为线性变换；按5.2.1附加假想力，构件P-δ仍按第8章稳定公式处理，不声称直接分析法。满足二阶条件后采用μ=1。正包络充分条件不成立不证明真实失稳。
- 梁侧扭用整根物理梁长度；端矩、分布力、集中力与偶矩分解后取绝对上界。物理整梁挠度以物理两端弦线计算，不在网格节点归零。
- 分量/位置/工况保守包络不是同时内力向量；满足充分上界可通过，不满足可能需精算。γ、β及抗震承载力调整均不借用有利系数制造通过。
- 扭转位移比1.2用于不规则分类，不能直接当作强度失败；采用三维、双向和偶然偏心处理后按1.5控制。完整建筑构造仍须交接验证。

## 状态与分工

`analysis_status`只表示分析完成；`design_status`表示声明边界内的上部杆系数值验算；`file_generation_status`表示文件输出。存在FAIL/PENDING不会因生成文件而改成PASS。`building_status`始终保留`EXTERNAL_VERIFICATION_PENDING`，直到相关组员完成其负责对象。

计算/结构组核对真实工程输入、模型适用性、材料表及参数；连接组实现梁端防扭、潜在塑性铰区双翼缘侧向支承、加劲肋焊缝、节点域和GL2刚接/GL3铰接性能；楼板组实现面内刚性及洞口传力；柱脚与基础组实现固定端假定。温度、施工阶段、火灾等专项适用作用另行核定。不可将课程计算书用作施工图审查通过证明。

## 接口

- `office_design.run_office_design({bundle, options}, progress, cancelled)`：独立Python入口；返回运行号、源/最终输入及模块SHA-256、逐轮记录、工况、组合、验算及10组二阶直接对照。
- `GET /workflow/office-design/reference`：返回明确标识的新课程案例。
- `POST /workflow/office-design/run-stream`：接收`{payload:{bundle,options}}`，SSE推送`workflow_started`、`office_progress`、`workflow_completed`，以运行号隔离。
- `GET /workflow/office-design/runs/{run_id}`：进度与结果摘要。
- `POST /workflow/office-design/runs/{run_id}/cancel`：请求停止；检查点之间允许当前一次OpenSees调用结束。
- `GET /workflow/office-design/runs/{run_id}/viewer/{case_id}`：实际静力工况图。
- `GET /workflow/office-design/runs/{run_id}/members/{member_id}`：物理构件详算。
- `POST /workflow/office-design/outputs`：仅接收服务端真实`run_id`，拒绝客户端拼装验算；重复请求复用同一文件清单。
- LangChain薄适配：`generate_office_calculation_book(run_id)`、`generate_office_design_files(run_id)`。

所有工况使用原XYZ、Z竖向，几何m，截面/位移mm，力kN、弯矩kN·m、应力MPa、转角rad。H梁腹板竖直时局部x从I指向J，局部y竖向，局部z=x×y；每个构件的三个局部基向量在结果中显式保存。杆端力是OpenSees单元端作用，I端轴力正为压缩；截面恢复使用局部q：N(x)=Ni+qx·x、My(x)=Myi+Vzi·x+qz·x²/2、Mz(x)=−Mzi+Vyi·x+qy·x²/2（x用m）。杆端作用与截面内力在J端采用相反截面法向，不能直接拼接同号。

```text
局部x及里程： I ─────────────────→ J
                      ↑ 局部y
局部z：x × y（右手系）
I端作用：[Ni,Vyi,Vzi,Ti,Myi,Mzi]
J端作用：[Nj,Vyj,Vzj,Tj,Myj,Mzj]
```

输入哈希采用排序JSON并将数值相等的整数/整值浮点统一（4与4.0相同），保留字符串与数值的区别，拒绝NaN/Infinity。浏览器、CLI与服务端因JSON往返不会产生虚假输入变更。

## Linux Docker配置

提供`Dockerfile.office`及`docker-compose.office.yml`，使用`docker compose -f docker-compose.office.yml up --build`启动。选用linux/amd64以匹配OpenSeesPy Linux依赖，Apple Silicon通过Docker的跨架构运行能力执行。前端8080、后端8000只映射本机；成果持久化到独立Docker卷，依赖安装在容器中。远程部署须将`STEEL_TOOL_PUBLIC_URL`及允许来源设置为用户浏览器可访问的地址。本次未进行Docker镜像构建/运行验收，不能将本地Mac验收等同容器验收。
