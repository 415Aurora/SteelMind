## 1 项目概述

### 1.1 项目背景

钢结构框架方案设计通常需要整理建筑与结构几何、材料、荷载、场地和规范依据，再进行结构分析、构件验算、截面调整和图表编制。资料分散、重复录入和计算过程难追溯，会增加方案比选和初步验算的工作量。结构工程师还需要在规范文本、截面资料、分析软件和成果文件之间反复切换。

SteelMind 钢结构智能设计助手面向钢框架方案阶段，尝试把自然语言交互、可编辑参数表、本地规范知识检索、Python 工程工具和工作流编排放在一个网页中，帮助用户形成一条输入清楚、步骤可查看、结果可复核的辅助设计链路。

### 1.2 要解决的工程问题

- 将项目描述转成结构化的地区、几何、材料、荷载和构件参数，减少遗漏与重复录入。
- 从本地规范知识库检索相关条文和地区参数线索，方便设计人员核对依据。
- 将荷载组合、框架分析、构件验算和截面调整组织成可追踪的步骤，减少工具之间的手工搬运。
- 汇总构件验算状态并在框架展示中定位构件，辅助发现需要复核或调整的部位。
- 把已生成的参数、计算与方案级图纸文件集中展示和下载，便于交流、审查与后续完善。

### 1.3 建设目标与定位

本项目的目标是构建钢结构框架智能设计辅助原型。系统通过大模型承担对话理解和说明，通过确定性 Python 工具处理参数检查、规范检索、数值分析、构件检查和文件生成；LangChain LCEL 负责按照预先定义的步骤编排工具，并记录每一步的输入输出。

系统当前用于方案研究、教学演示和工程师辅助复核。生成的分析结果、验算结论及图纸均需由具备相应职责的专业人员核对。当前原型不替代正式设计软件、规范审查、注册工程师判断或施工图设计。

## 2 总体设计思路

### 2.1 人机协同原则

用户可在对话中描述需求，也可直接编辑网页中的结构化表格。智能体可以根据对话建议填写参数，但参数必须能被用户查看和修改。对于缺失或含义不明确的输入，系统应提示补充或明确假定，不应把假定值伪装为已知工程数据。

大模型负责理解表达、整理信息、解释工具结果和协助生成说明；工程数值由后端工具执行。计算过程不应由大模型凭语言生成内力、验算数值或规范结论。规范 RAG 的检索片段用于定位依据，适用版本、条文、表格条件及参数仍须人工核实。

### 2.2 系统处理链路

系统将设计过程拆为输入与校核、知识检索、初步建模、构件验算、截面迭代、成果导出六个环节。网页向本地 FastAPI 工具网关发送结构化请求；网关加载工具，LCEL 工作流按顺序调用工具，并通过流式事件向网页返回阶段状态、调用输入与输出。结果可进入三维框架视图或工程文件下载区。

### 2.3 技术组成

- **网页前端：** 单页 HTML/JavaScript 应用，提供配置、聊天、参数表、工作流、可视化和成果入口。
- **大模型接口：** 使用用户配置的 OpenAI 兼容接口地址、模型名称和 API Key。API Key 在网页运行期间由用户填写，不应写入仓库或公开页面源代码。
- **Python 工具网关：** FastAPI 服务，负责工具注册、参数传递、健康检查、工作流流式响应和文件下载。
- **工作流编排：** LangChain LCEL 将确定性工具组合成工作流，并提供调用跟踪。
- **工程工具：** 参数校验、荷载组合、截面查询、OpenSeesPy 分析、钢构件验算、截面迭代、可视化和成果生成等。
- **规范知识库：** 从项目本地机器可读规范库检索内容，支持选择规范目录。
- **文件存储：** 默认存入本地 `backend/artifacts/` 并由网关提供下载；对象存储为可选配置。

## 3 网页模块说明

| 页面 | 主要功能 | 使用目的 |
|---|---|---|
| 模型与知识库配置 | 设置模型服务地址、模型名称、API Key 和系统提示词；选择是否启用本地规范知识库及检索目录；上传或下载建模参数模板 | 配置对话服务和知识来源，准备可供工作流读取的输入 |
| 对话 | 与设计助手进行连续对话；查看本次会话消息、停止生成、查看历史会话；通过对话补充或调整设计参数 | 表达设计需求、询问结果、协助填写结构化参数 |
| 工具与工作流 | 编辑工具或工作流所需参数；运行单项工具及“信息获取与截面初选”“截面迭代与优化”；查看每个步骤的状态、输入和输出 | 执行并跟踪工程计算过程，诊断失败步骤 |
| 可视化与结果导出 | 展示 OpenSees 框架模型、构件状态和截面；进入工程文件输出工作流；查看和下载计算书、参数表及方案图纸等产物 | 观察模型与验算状态，检查并获取本次生成文件 |

### 3.1 模型与知识库配置

用户在此配置所使用的大模型服务。接口需与 OpenAI Chat Completions 兼容，并填写与服务端匹配的模型标识。系统提示词用于说明助手角色和任务边界。知识库开关决定是否启用项目本地规范 RAG；目录选项用于缩小检索范围。参数模板供批量整理模型输入。

API Key 属于敏感凭据。使用时只在可信网页中填写，不要将密钥写入 HTML、配置文件或 Git 仓库。线上网页调用本地 Python 工具时，还需要本机网关正常运行并允许浏览器访问；仅配置大模型并不代表工程工具网关已连接。

### 3.2 对话

对话页面用于自然语言交流、提供项目背景、追问缺失信息和理解工具结果。聊天模型负责对话生成；工程计算需通过单项工具或工作流执行。用户应将重要结构参数同步核对到工作流表格，并在计算前确认单位、方向、边界条件和荷载含义。

### 3.3 工具与工作流

该页面包含可单独调用的工程工具，以及前两条设计工作流。用户可直接编辑参数表，也可先通过对话整理后再检查表格。执行期间页面按工作流事件显示阶段和工具输入输出，便于定位校验失败、工具异常或不完整数据。

### 3.4 可视化与结果导出

框架视图用于旋转、缩放和平移模型；在已关联验算数据时，可选中构件查看其截面和检查指标，并用颜色辅助识别状态。当前空间视图表达几何和结果信息，不应被理解为完整三维 OpenSees 计算模型。结果导出区域运行第三条工作流，并提供本次生成文件的链接；下载前需检查文件状态、草稿标记、数据完整性和警告。

## 4 三条设计工作流

### 4.1 信息获取与截面初选

该流程接收项目基本信息，先由参数校验工具检查几何、材料和荷载字段，再从本地规范 RAG 检索有关条文或地区参数线索，随后执行荷载组合及初步框架分析，并利用候选截面和已有检查工具形成初选建议。流程输出包括输入校核、检索记录、分析和初选结果。初选是后续迭代的起点，不代表截面已满足所有规范要求。

### 4.2 截面迭代与优化

该流程以初始框架参数和有序候选截面为输入，循环执行 OpenSeesPy 分析和构件验算，并根据检查结果调整截面，再用调整后的截面重新分析。工作流保留每轮截面、利用率、检查状态和工具跟踪记录；仅当最终实际参与分析的模型通过已实现检查项时，才报告流程收敛。候选截面耗尽、迭代上限或工具错误时，应返回未收敛或失败信息。

当前截面调整依赖离散候选集合，是有界筛选与重分析，不是全局质量最优的连续数学优化。其收敛结论只对应当前输入、分析模型与工具实现的检查范围。

### 4.3 工程文件输出

该流程接收第二条工作流的最终报告，检查是否收敛、构件验算记录和图纸数据契约，然后生成计算书、参数结果表及二维 DXF/PDF 方案图等文件。缺失关键数据时，流程会拒绝导出或以部分/草稿状态返回，不应通过默认值补造结构数据。生成完成后，网页展示文件名称、类型、状态和下载入口。

## 5 使用说明

1. **启动系统：** 在项目根目录运行 Windows 启动器 `start_tool_gateway.bat`，或在 Linux/macOS 使用相应 Shell 启动脚本。首次启动会创建或补齐 Python 环境并安装依赖；启动窗口需保持运行。访问 `http://127.0.0.1:8000/health` 检查本地网关状态，网页入口为 `http://127.0.0.1:8000/`。
2. **配置模型与知识库：** 在“模型与知识库配置”页填写兼容接口、模型及 API Key；按需开启规范知识库并选定检索目录。保存前核对接口地址及模型 ID。
3. **准备结构输入：** 使用参数模板或网页表格录入项目、地区、几何、材料、荷载和截面候选数据。核实单位、跨数、跨度、层数、层高、支承和荷载作用方向。
4. **运行初选：** 在“工具与工作流”页运行“信息获取与截面初选”，阅读缺项提示、规范检索来源、分析结果及截面建议。
5. **迭代验算：** 将确认后的输入和候选截面送入“截面迭代与优化”。查看每轮模型截面、构件验算和收敛状态；出现失败或未收敛时，先检查输入和工具输出，再修改候选截面或模型假定。
6. **查看模型和输出文件：** 在“可视化与结果导出”页检查模型、构件截面与验算指标，确认工作流2结果后运行“工程文件输出”。逐项查看导出状态、草稿标记、警告和文件内容。
7. **归档复核：** 保存输入参数、规范检索记录、工作流运行结果和下载产物，使后续复核能够重现本次分析条件。

## 6 输入、输出与数据管理

### 6.1 主要输入

| 输入类别 | 示例字段 | 复核要点 |
|---|---|---|
| 项目与地区 | 项目名称、地点、设防相关信息 | 地区名称及参数来源、规范版本与适用条件 |
| 几何 | X/Z方向跨数与跨度、层数、层高、支承 | 单位、方向定义、几何是否与结构布置一致 |
| 材料与截面 | 钢材牌号、梁柱截面、候选截面 | 截面库来源、型号、截面属性与材料参数 |
| 荷载 | 恒载、活载、风、地震或线荷载输入 | 特征值、单位、施加位置、方向、组合及作用范围 |
| 验算控制 | 计算长度、挠度限值、目标利用率和迭代上限 | 参数的依据与是否适用于具体构件和用途 |

### 6.2 主要输出

系统可返回参数检查与规范检索记录、荷载组合结果、框架分析结果、构件内力及位移数据、逐构件验算明细、截面迭代记录、框架可视化数据，以及计算书、Excel 参数表和 DXF/PDF 方案级图纸。实际可生成的文件取决于输入完整性、工具依赖和本次运行状态。

### 6.3 知识库和运行文件

规范检索读取项目目录 `Knowledge/07_机器可读规范库/` 中的机器可读数据和索引，由 `Knowledge/08_规范RAG工具/` 提供检索实现。工具网关运行代码位于 `backend/`，网页位于 `dist/`，默认生成文件存放于 `backend/artifacts/`。若配置对象存储，文件保存位置可能由运行配置决定。

## 7 适用边界与后续完善

当前框架分析工具以二维、线弹性、单次静力分析为主。空间视图可呈现两个方向的几何，但不意味着求解器已完成空间结构分析。现有模型对弱轴效应、扭转、连接刚度、二阶效应、多工况包络、基础与构造措施等方面存在明确限制；部分验算项目仍属于筛查实现。计算长度、荷载组合、限值及材料参数需按项目条件审查。

工程成果包目前属于方案级辅助输出。图纸不含完整节点连接、螺栓/焊缝、基础与施工详图；单一分析工况也不能替代规范要求的完整极限状态组合。若输入或上游验算不完整，文件可能标记为草稿、INCOMPLETE 或 partial。不得仅根据页面“收敛”状态或图纸外观作出结构安全结论或直接用于施工。

后续可优先完善真实三维有限元分析、多规范荷载组合与包络、稳定和构造验算、工程师复核闭环、RAG 条文定位准确性、计算书条文引用、节点与基础设计，以及面向正式图纸的校核和签审流程。
