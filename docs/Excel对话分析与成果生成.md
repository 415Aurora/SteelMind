# Excel 对话分析与成果生成

适用入口：本地网页 → 连接与知识库 → 上传已填写的 Excel → 对话工作台。
本次接通现有 Excel 原始 XYZ 杆系自重计算通道；不将其转为规则框架，不扩大为尚未完成联调的办公楼恒活风震设计。

## 操作

1. 配置支持工具调用的模型服务，保存 API 配置，并确认本地工具网关可访问。
2. 在当前会话上传 Excel，确认显示已读取节点和杆件。
3. 在对话框发送：“请分析刚上传的Excel原模型，按当前支持的自重范围执行计算，并列出验算通过、失败、不适用和待补充项。”
4. 追问：“请查看构件C001的实际验算记录，解释利用率、公式与依据。”将C001替换为本次模型实际编号。
5. 发送：“请根据当前Excel模型生成计算书、结果表和图纸，并保留缺项。”
6. 从回复中点击真实下载链接，也可到“模型与成果 → 工程文件输出”查看文件列表；三维模型与工作流2结果同步更新。

可在一句话中要求“分析当前Excel并生成成果”。对话的模型须支持OpenAI兼容工具调用；没有API Key的演示回复不会执行自然语言任务。输入框旁的“生成计算书/图纸”按钮不依赖大模型，可自动先分析Excel再生成成果。

## 接口及状态

- `analyze_excel_model({})` 调用 `/workflow/explicit-model/run`，输入来自当前上传表格，不接受模型生成的替代输入。
- `get_excel_results({member_id?})` 读取本次真实结果，返回原始编号、控制记录、位移、验算统计及工程缺项。
- `generate_engineering_package({})` 对Excel调用 `/workflow/engineering-outputs/run-stream`，传入 `explicit_tables`；规则框架仍传 `final_report`。
- 工作流2按钮和对话共用前端会话结果；上传新表格、切换会话、输入变化后结果失效。分析期间输入变更时丢弃旧返回。
- 原模型自重成果保留草稿标识。文件生成状态与结构验算汇总分别显示，FAIL与PENDING不会升级为PASS。
- 不支持通过聊天直接修改原Excel节点/杆件，也不把聊天中的建议静默写入模型。

## 验证

新增Node工具回合与状态隔离测试。`backend/tests/verify-chat-excel-live.cjs`可对正在运行的本地网关执行真实案例分析、生成及全部文件下载SHA-256校验；模型侧采用可重复的工具调用模拟，不代表已测试真实服务商API。

2026-11-05验收：Python全量回归322通过（2条既有FastAPI生命周期弃用提示）；Node回归29通过（含新增9项对话测试）。龙岩120节点/248杆件案例通过真实本地HTTP接口完成分析、指定构件查询、成果生成及36份文件逐一下载SHA-256校验。保留原验算汇总INCOMPLETE：1472通过、0失败、600待补充、616不适用；没有将文件成功改写为完整设计通过。模型侧为确定性工具调用模拟，真实服务商的选工具行为仍取决于所配置模型；本次没有使用或验证用户真实API Key。

### 浏览器缓存兼容

若出现`createExcelSession is not a function`，是页面与对话脚本版本不一致，不是模型API连接失败。页面现以脚本内容SHA-256前12位作为`chat-tools.js?v=...`的版本参数，并有版本检查测试。更新后在Safari按Option+Command+R重新载入，再确认当前会话的Excel已导入并重发问题即可，无需修改API Key。
